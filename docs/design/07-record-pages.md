# Plan 07: Record Pages and Page Layouts

## Overview

The three custom objects — `bcm_Map__c`, `bcm_Capability__c`, and `bcm_Tag__c` — require defined record pages, page layouts, and related list configurations to support the standard Create/View/Edit/Delete functional processes. This document specifies those definitions.

`bcm_CapabilityTag__c` is a junction object managed exclusively through related lists on its two parent records; it does not have a standalone record page.

---

## bcm_Map\_\_c

### Tab and Navigation

`bcm_Map__c` does not have an Object Tab in the `bcm_BusinessCapabilityMap` app (the Map combobox on the diagram page serves as the primary navigation entry point). Editors access Map records directly via record URLs or via a list view reachable through the App Launcher or the standard object URL.

To provide a minimal management path without adding a tab, a **Map list view** is accessible at the standard object URL and is sufficient for Editors to create, rename, and delete Maps.

**Addition to the app:** Add a **Maps** Object Tab to the `bcm_BusinessCapabilityMap` app, visible to `bcm_Editor` users only.

| Tab # | Label | Type       | Object       | Visible To        |
| ----- | ----- | ---------- | ------------ | ----------------- |
| 5     | Maps  | Object Tab | `bcm_Map__c` | `bcm_Editor` only |

> This corrects the gap identified during functional size measurement. Without this tab there is no in-app path for Editors to create or delete Maps.

### List View

**Default list view — All Maps**

| Column      | Field                |
| ----------- | -------------------- |
| Name        | `Name`               |
| Description | `bcm_Description__c` |

Sort: `Name` ASC

### Page Layout — bcm_Map Layout

Single-column layout.

**Details section**

| Field                | Read-only in layout |
| -------------------- | ------------------- |
| `Name`               | No                  |
| `bcm_Description__c` | No                  |

### Related Lists on Map Detail Page

| Related List | Object              | Columns                         | Sort                      |
| ------------ | ------------------- | ------------------------------- | ------------------------- |
| Capabilities | `bcm_Capability__c` | Name, Level, Parent, Sort Order | Level ASC, Sort Order ASC |

### FlexiPage

Standard Lightning record page generated by Salesforce. No custom FlexiPage required — the default layout (Details tab + Related tab) is sufficient.

**API Name:** `bcm_Map__c-bcm_Map_Layout` (auto-generated)

## bcm_Capability\_\_c

### Page Layout — bcm_Capability Layout

Two-section layout.

**Section 1 — Identity**

| Field               | Read-only in layout |
| ------------------- | ------------------- |
| `Name`              | No                  |
| `bcm_Map__c`        | No                  |
| `bcm_Level__c`      | No                  |
| `bcm_Parent__c`     | No                  |
| `bcm_SortOrder__c`  | No                  |
| `bcm_ExternalId__c` | No                  |

**Section 2 — Narrative**

Each field occupies a full-width row (single column within section).

| Field                        | Read-only in layout |
| ---------------------------- | ------------------- |
| `bcm_Definition__c`          | No                  |
| `bcm_StrategySupport__c`     | No                  |
| `bcm_ArchitecturalNuance__c` | No                  |

### Related Lists on Capability Detail Page

| Related List | Object                 | Columns              | Sort         |
| ------------ | ---------------------- | -------------------- | ------------ |
| Tags         | `bcm_CapabilityTag__c` | Tag Name, Tag Colour | Tag Name ASC |

**Note on the Tags related list:** The related list object is `bcm_CapabilityTag__c`. Columns display the related `bcm_Tag__c` fields (`bcm_Tag__r.Name`, `bcm_Tag__r.bcm_Colour__c`). The **New** action on this related list opens a `bcm_CapabilityTag__c` creation dialog with the Capability pre-filled and a Tag lookup for the Editor to complete. The **Delete** row action removes the junction record without affecting the Tag.

### FlexiPage

Standard Lightning record page. No custom FlexiPage required.

## bcm_Tag\_\_c

### Page Layout — bcm_Tag Layout

Single-section layout.

**Section — Identity**

| Field           | Read-only in layout |
| --------------- | ------------------- |
| `Name`          | No                  |
| `bcm_Colour__c` | No                  |

**Help text on `bcm_Colour__c`:** "Choose a colour from the list. This colour will highlight Capabilities tagged with this Tag on the diagram."

### Related Lists on Tag Detail Page

| Related List | Object                 | Columns              | Sort                |
| ------------ | ---------------------- | -------------------- | ------------------- |
| Capabilities | `bcm_CapabilityTag__c` | Capability Name, Map | Capability Name ASC |

**Note on the Capabilities related list:** The related list object is `bcm_CapabilityTag__c`. Columns display `bcm_Capability__r.Name` and `bcm_Capability__r.bcm_Map__c`. The **New** action is hidden — Tags are associated to Capabilities from the Capability detail page, not the other way around. Only the **Delete** row action is available to Editors.

### FlexiPage

**API Name:** `bcm_Tag_Record_Page` — custom FlexiPage deployed in Step 3.

**Regions:**

- `header` — `force:highlightsPanel`
- `main` — `bcm_ColourSwatch` (colour preview, above tabs), then `flexipage:tabset` (Detail tab + Related tab)
- `sidebar` — empty

**`bcm_ColourSwatch` LWC:** Display-only component. Wraps a `lightning-card` (title "Colour", icon `utility:color_swatch`) whose body is a full-width block filled with the stored hex value as `background-color`. The colour name is rendered as white centred text inside the block; if no colour is set, the card body shows "No colour set" in muted text. The target field is configurable at design time via the `colourField` property (default `bcm_Tag__c.bcm_Colour__c`), allowing the component to be reused on any record page. No Apex, no DML. Visible to all users with Read access. Source: `force-app/main/default/lwc/bcm_ColourSwatch/`.

## Validation Rules Surfaced in the UI

The following validation rules (defined in `01-data-model.md`) will fire on save and display inline errors via the standard Salesforce record form error handling:

| Object              | Rule                                                                                            | Error Message                                      |
| ------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `bcm_Capability__c` | Level must be 1, 2, or 3                                                                        | "Level must be 1, 2, or 3."                        |
| `bcm_Capability__c` | If Parent is null, Level must be 1                                                              | "A capability with no parent must be Level 1."     |
| `bcm_Capability__c` | If Parent is set, Level must be 2 or 3                                                          | "A capability with a parent must be Level 2 or 3." |
| `bcm_Tag__c`        | Colour is a required restricted picklist — invalid or blank values are rejected by the platform | Standard picklist error message                    |

No custom LWC error handling is required for these — Salesforce renders validation rule messages inline on the standard record form.

## Permission Set Additions

The `bcm_Editor` permission set (defined in `06-app-structure.md`) requires the following addition to support the Maps tab:

| Setting               | Value      |
| --------------------- | ---------- |
| Tab Visibility — Maps | Default On |

The `bcm_Viewer` permission set requires:

| Setting               | Value  |
| --------------------- | ------ |
| Tab Visibility — Maps | Hidden |

> Viewers have Read access to `bcm_Map__c` records but Map management is an Editor function. Viewers reach Map data through the diagram combobox, not through the Maps tab.
