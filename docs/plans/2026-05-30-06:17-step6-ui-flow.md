# Plan: Step 6 UI — Flow-based Import (replaces bcm_ImportUtility LWC)

## Context

Step 6 Apex is complete (`bcm_ImportController` + test class). The original plan called for an LWC `bcm_ImportUtility` embedded in `bcm_ImportButton`. We are replacing that with a Screen Flow (`bcm_Import_Flow`) instead. The LWC approach required writing all UI state management, error display, and spinner logic manually. The Flow approach gets those behaviours declaratively and is consistent with how Salesforce-native tooling works.

`bcm_ImportButton` still exists and will be updated to embed the Flow via `lightning-flow` rather than the `bcm_ImportUtility` LWC (which will never be created).

## Key Design Decision — Remove @AuraEnabled, Add @InvocableMethod in Place

`@InvocableVariable` and `@AuraEnabled` cannot coexist on fields in the same class. Since no LWC is calling `bcm_ImportController` directly anymore, we simply **remove `@AuraEnabled`** from `importCapabilities` and from the `bcm_ImportResult` fields. This lets us add `@InvocableMethod` + `@InvocableVariable` directly inside `bcm_ImportController` — no separate wrapper class needed.

Changes to `bcm_ImportController.cls`:

1. Remove `@AuraEnabled(cacheable=false)` from `importCapabilities` (method stays `public static`)
2. Remove `@AuraEnabled` from all four `bcm_ImportResult` fields; add `@InvocableVariable` to each
3. Add `FlowInput` inner class with `@InvocableVariable String jsonPayload`
4. Add `@InvocableMethod execute(List<FlowInput>)` that calls `importCapabilities` and **catches `AuraHandledException`** (thrown by permission check), mapping it to a `bcm_ImportResult` with `success=false` rather than re-throwing (an unhandled exception in a Flow action produces a broken generic error screen)

`bcm_ImportControllerTest.cls` calls `importCapabilities()` directly — it needs only two additional test methods for the `execute()` path.

## Phase 1 — Apex: Modify `bcm_ImportController`

**Skill:** `generating-apex` (for the edits) then extend `bcm_ImportControllerTest` via `generating-apex-test`

### Changes to `bcm_ImportController.cls`

**`bcm_ImportResult`** — swap annotations:

```apex
public class bcm_ImportResult {
    @InvocableVariable
    public Integer capabilitiesInserted;
    @InvocableVariable
    public Integer capabilitiesUpdated;
    @InvocableVariable
    public Boolean success;
    @InvocableVariable
    public String errorMessage;
}
```

**`importCapabilities`** — remove `@AuraEnabled(cacheable=false)`, keep signature `public static bcm_ImportResult importCapabilities(String jsonPayload)` unchanged.

**New inner class and method (append to class body):**

```apex
public class FlowInput {
    @InvocableVariable(label='JSON Payload' required=true)
    public String jsonPayload;
}

@InvocableMethod(
    label='Import Capability Map from JSON'
    description='Calls importCapabilities and surfaces result for a Screen Flow.'
    category='BCM'
)
public static List<bcm_ImportResult> execute(List<FlowInput> inputs) {
    try {
        return new List<bcm_ImportResult>{ importCapabilities(inputs.get(0).jsonPayload) };
    } catch (AuraHandledException e) {
        bcm_ImportResult err = new bcm_ImportResult();
        err.success      = false;
        err.errorMessage = e.getMessage();
        err.capabilitiesInserted = 0;
        err.capabilitiesUpdated  = 0;
        return new List<bcm_ImportResult>{ err };
    }
}
```

## Phase 2 — Flow: `bcm_Import_Flow`

**Skill:** `generating-flow` (mandatory 3-step MCP pipeline: `fetchGroundedObjectMetadata` → `flowElementSelection` → `flowElementGeneration`)

**Flow type:** Screen Flow

**User prompt for the pipeline:**

> Create a Screen Flow named `bcm_Import_Flow` with label "Import Capability Map". Screen 1 has a Long Text Area input variable `jsonPayload` (label "Paste JSON", required). After Screen 1, call Apex action `bcm_ImportController` (method `execute`) passing `jsonPayload`, storing outputs into Boolean `importSuccess`, Text `importErrorMessage`, Number `capabilitiesInserted`, Number `capabilitiesUpdated`. Then a Decision element: if `importSuccess` equals `true`, go to Screen 2a (Display Text "Successfully imported {capabilitiesInserted} capabilities." and a Finish button labelled "Close"); otherwise go to Screen 2b (Display Text showing `importErrorMessage`, with a Previous button so the user can go back to Screen 1).

**inflightMetadata:** empty array `[]` — the Flow invokes an Apex action and does not directly reference any custom object fields.

**After generation:** write the resulting XML to `force-app/main/default/flows/bcm_Import_Flow.flow-meta.xml`.

```html
</template>
```

### `bcm_ImportButton.js`

Replace `close()` with `handleStatusChange`:

```js
import { LightningElement } from 'lwc';

export default class BcmImportButton extends LightningElement {
    handleStatusChange(event) {
        const s = event.detail.status;
        if (s === 'FINISHED' || s === 'FINISHED_SCREEN') {
            this.dispatchEvent(new CustomEvent('closeactionpanel'));
        }
    }
}
```

Both `FINISHED` and `FINISHED_SCREEN` are checked because the status depends on whether the last element in the Flow topology is a screen — testing on-org will confirm which fires, but handling both is safe.
