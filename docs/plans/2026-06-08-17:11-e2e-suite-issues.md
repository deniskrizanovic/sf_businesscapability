# E2E Suite — Outstanding Issues

Captured 2026-06-08 after a debug session that diagnosed cross-spec data wipes and put the suite into a clean state. This doc is a hand-off list to deal with in a future session.

## Context recap

- Earlier WebStorm runs: 9–13 random failures across 95 tests, different tests each run.
- Concurrency was the dominant root cause. Set `workers: 1` in `playwright.config.ts` (already had `fullyParallel: false`).
- Post-`workers: 1`, failures collapsed into one cluster: 8 of 9 in `drag-drop.spec.ts` plus 1 viewer detail-panel test.
- Root cause of the cluster: per-spec `afterAll` teardowns in `diagram.spec.ts` and `capability-detail.spec.ts` were deleting capabilities by `bcm_Map__r.Name LIKE '%RUN_ID%'` with no Map-name filter. With deterministic alphabetical ordering, `diagram.spec.ts` teardown ran before `drag-drop.spec.ts`, wiping its seed.
- Fix landed in this session: removed both per-spec teardowns. `globalTeardown` is now the single source of cleanup.
- Design doc written: `docs/design/09-e2e-test-architecture.md`.

## Issues to address

### 4. Validate alphabetical-order safety

With `workers: 1 + fullyParallel: false`, spec files run alphabetical. Any cross-spec dependency is a latent bug. Audit:

- Does any spec assume seed data created by another spec?
- Does any spec mutate seed data in a way that breaks a later spec?

The drag-drop gesture test mutates `bcm_SortOrder__c` for `L2A1_NAME`/`L2A2_NAME`. Verify subsequent drag-drop outcome tests don't depend on the original order — visually scan `drag-drop.spec.ts:95–203`.

### 5. Decide on retries

Currently no `retries` set. Quality Plan and the new design doc both say "diagnose, don't paper over". Once the suite is reliably green at `workers: 1`, decide:

- Stay at `retries: 0` (preferred — flake stays visible).
- `retries: 1` only if a specific Salesforce platform jitter class is identified and documented by name.

### 6. CI integration (deferred but listed)

The suite is run manually. If/when the project becomes multi-developer, a GitHub Actions job that runs `npx playwright test` against a scratch org becomes the next priority. Out of scope for this round.

### 7. Spec scenarios that depend on `MAP_NAME` not being mutated

`capability-detail.spec.ts` selects `MAP_NAME` in roughly 15 places. If any test path mutates the map's record (rename, delete, hide-from-diagram), all subsequent tests in the file break. Quick audit pass — search for `update map` / `delete map` style writes in this spec.

### 8. Stale temp files

`fixtures/seeds.ts`, `drag-drop.spec.ts` (`runApex`, `parseDragDropOrder`) all write `*.apex` temp files into `tests/e2e/` and `unlink` them in `finally`. A crashed test can leave files behind. Add to `.gitignore` (likely already covered by `.dd_*`/`.seed_*` patterns) and confirm `globalTeardown` is robust against stale files (it should not be — but worth a glance).

```
ls tests/e2e/.{dd,seed,teardown}_* 2>/dev/null
```

### 9. Performance

13:24 wall-clock for 95 tests at `workers: 1`. Acceptable for now, painful in the long run. Levers:

- Restore concurrency *only across specs that don't share an org user* (would require multiple test users — adds setup complexity).
- Reduce navigation: many tests do `goto('/lightning/n/bcm_Visualisation')` + `selectMap`. Could cache via `storageState` or per-describe `beforeAll` page reuse — but only for read-only tests.
- Lazy-load seeds: `globalSetup` currently seeds three feature payloads even if only one spec runs. Acceptable; not an early optimisation target.

### 10. `setupAutoDismiss` is global mutation

`setupAutoDismiss` installs MutationObservers via `addInitScript`. If a future test relies on one of the stripped overlays (e.g. testing onboarding), it will quietly fail. Document this in the helper itself or add a `disableAutoDismiss` opt-out param. Low priority until needed.

### 11. `fixtures/auth.setup.ts` does not refresh tokens

Sessions are saved to `tests/e2e/.auth/*.json` per run. If the storage state expires mid-run (rare; ~hours), tests fail with auth redirects. Out of scope but worth noting if mysterious mid-run failures appear.
