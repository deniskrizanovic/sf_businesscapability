**`bcm_DragDropController` (with sharing):**

```apex
@AuraEnabled
public static void reorderCapabilities(List<Id> orderedIds)
```
- Custom-permission gate (`FeatureManagement.checkPermission('bcm_CanEdit')`) → `AuraHandledException("Access denied.")` on miss.
- Empty / null `orderedIds` → silent no-op.
- Builds `List<bcm_Capability__c>` writing `bcm_SortOrder__c = 1..N`. Single `update`. Wraps DML errors as `AuraHandledException`.

```apex
@AuraEnabled
public static void reparentCapability(
    Id capabilityId,
    Id newParentId,
    List<Id> newSiblingIds,
    List<Id> oldSiblingIds
)
```
- Custom-permission gate first line.
- Reads moved capability + new parent (if not null) — assert same `bcm_Map__c`. Cross-map → `AuraHandledException`.
- Computes new level: `newParentId == null ? 1 : newParent.bcm_Level__c + 1`. Assigns to moved node.
- Queries descendants of moved node `WITH SECURITY_ENFORCED` (SOQL up to one level given the L3 cap; safe loop covers any future depth change).
- Recalculates descendant `bcm_Level__c` (`level = parentLevel + 1` cascade).
- Writes sequential `bcm_SortOrder__c` to `oldSiblingIds` and `newSiblingIds`.
- Groups all updates into a single `List<bcm_Capability__c>` and one `update` call.
- Trigger + validation rules enforce the L1/L2/L3 invariants — Apex re-throws platform DML errors as `AuraHandledException`.

**`bcm_DragDropControllerTest` (≥75% coverage; mandatory permission-boundary tests per CLAUDE.md):**

|---|---|

### 8c — LWC: drag state machine + Apex wiring (split into 5 micro-steps)

`bcm_CapabilityMap.js`:

**New imports:**
```js
import reorderCapabilities from '@salesforce/apex/bcm_DragDropController.reorderCapabilities';
import reparentCapability from '@salesforce/apex/bcm_DragDropController.reparentCapability';
import { ShowToastEvent } from 'lightning/platformShowToast';
```

**New tracked state:**
```js
isDragging          // boolean
isSavingDragDrop    // boolean — handles + map combobox blocked while true
draggedNodeId       // Id
draggedNodeLevel    // 1 | 2 | 3
ghostX, ghostY      // viewport coords
ghostOffsetX, ghostOffsetY  // grab-point offset
dropTargetInfo      // { parentId | null, position: number, level: 1|2|3 } | null
preDragSnapshot     // JSON.parse(JSON.stringify(this.capabilities)) at drag-start
```

**8c-i — State vars + drag start (`handleHandleMouseDown`):**
- Add tracked state vars listed above.
- `event.stopPropagation()` so pan listener doesn't fire.
- Capture node id, level, offset between cursor and node origin (in viewport coords).
- `isDragging = true`. `preDragSnapshot = JSON.parse(JSON.stringify(this.capabilities))`.
- Attach `mousemove`, `mouseup`, `keydown` (Escape) listeners on `window` (not SVG — cursor may leave SVG mid-drag).
- **Verify 8c-i:** Jest test `editor sees drag handles` + manual: handle mousedown sets `isDragging` (visible via 0.3 opacity on origin node); `mouseup` anywhere clears it without Apex.

**8c-ii — Drag move + drop hit-test (`handleDragMouseMove`):**
- Convert client coords → viewport coords (account for `panX`, `panY`, `zoom`).
- Update `ghostX`, `ghostY`.
- Recompute `dropTargetInfo` via gap-slot midpoint hit-test for the dragged level:
  - L1: which gap between `_layoutL1` x-positions is cursor closest to?
  - L2: which column does cursor fall in (x-strip), then which gap between L2 boxes in that column?
  - L3: which L2 box does cursor fall inside, then which gap between bullet rows?
- Empty column / empty L2 box: gap = single slot at top of body region.
- Cross-level rejection: if cursor is over wrong-level container, `dropTargetInfo = null`.
- **Verify 8c-ii:** Jest tests `ghost renders at cursor` + `drop indicator renders at target gap` pass.

**8c-iii — Drop optimistic + Apex call (`handleDragMouseUp`):**
- Detach window listeners.
- If `dropTargetInfo == null` OR drop is no-op (same parent + same index) → cancel: `isDragging = false`, `preDragSnapshot = null`. Return.
- Determine reorder vs reparent:
  - Same parent, different index → `reorderCapabilities(newSiblingIds)`
  - Different parent → `reparentCapability(movedId, newParentId, newSiblingIds, oldSiblingIds)`
- Apply optimistic mutation to `this.capabilities`: write moved node's `bcm_Parent__c`, rewrite affected siblings' `bcm_SortOrder__c` 1..N. Call `_assembleAndLayout()`. Diagram re-renders.
- Refresh Detail Panel breadcrumb if open and shows the moved node — recompute from new tree (existing breadcrumb-builder util).
- `isSavingDragDrop = true` → handles hidden, map combobox disabled.
- Fire Apex.
- **Verify 8c-iii:** Jest test `drop outside valid target cancels` passes. Manual: real drag against `home-denispoc` reorders an L2; refresh confirms persistence.

**8c-iv — Error revert + toast:**
- Success → `isSavingDragDrop = false`. `preDragSnapshot = null`. Done.
- Error → `this.capabilities = preDragSnapshot`. `_assembleAndLayout()`. ShowToastEvent variant `error`, mode `dismissable`, message `"Failed to save changes. Your changes have been reverted."`. `isSavingDragDrop = false`. `preDragSnapshot = null`.
- **Verify 8c-iv:** Jest test `apex error reverts and toasts` passes.

**8c-v — Escape + pan/zoom guards + map combobox lock:**
- `keydown` Escape while `isDragging` → cancel as if drop was outside valid target. No optimistic update applied yet (drop hasn't fired), no Apex, no toast.
- Pan/zoom guards (modify existing handlers):
  - `handleWheel`: early return if `isDragging`.
  - Keyboard arrow handler: early return if `isDragging`.
  - Pan `mousedown`: unaffected (handle's `stopPropagation` already prevents the conflict).
- Map combobox: `disabled={isSavingDragDrop}`.
- Permission gate: `canEdit` from existing `import hasPermission from '@salesforce/customPermission/bcm_CanEdit'`. Handle template guarded by `canEdit && !isSavingDragDrop`.
- **Verify 8c-v:** Jest test `escape cancels drag` passes. Manual: wheel + arrow keys silent during drag; map combobox momentarily disabled mid-Apex.
