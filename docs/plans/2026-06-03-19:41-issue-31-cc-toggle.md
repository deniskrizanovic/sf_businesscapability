# Issue #31 — Toolbar toggle to show/hide cross-cutting band (default hidden)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [x]`) syntax for tracking.

## Context

Issue #30 introduced the cross-cutting chevron band, currently always rendered when at least one L1 has `bcm_IsCrossCutting__c = true`. This slice adds a per-session UI toggle (default **hidden**) that gates band visibility AND reclaims the band's vertical space when hidden. Mirrors the existing `Show Hidden` toolbar pattern.

Out of scope:
- Persisting the toggle across sessions (no sessionStorage)
- Animating the layout reflow
- Per-capability filtering inside the band

---

## Architecture

**State:** new `@track showCrossCutting = false` on `BcmCapabilityMap`. Default `false` per AC.

**Toolbar:** new `lightning-button-icon` placed immediately after the `Show Hidden` button. Icon `utility:rows`, title `Cross-cutting`, `variant={crossCuttingVariant}` (brand when on, border when off — mirrors `showHiddenVariant`). `onclick={handleToggleCrossCutting}`.

**Visibility gating** — two coupled changes:

1. **Template:** wrap the existing band `<g transform={bandTransform}>…</g>` in `<template if:true={showCrossCutting}>` so the DOM contains zero `.bcm-band-node` when hidden.
2. **`canvasHeight` getter:** band reservation contributes only when `showCrossCutting && nrows > 0`. When hidden, height collapses back to `padding*2 + headerReserved + tallest`.

`bandNodes` getter and `_layoutBand` array remain populated regardless — geometry is still computed each `_buildLayout` so toggling on requires no re-layout, only a re-render. Cheap and keeps the toggle handler trivial.

**Map-switch reset:** `handleMapChange` already resets zoom/pan; add `this.showCrossCutting = false` so per-map state defaults to hidden, matching AC "Switching maps resets the toggle to hidden".

**Toggle handler:** flip `showCrossCutting`. No layout rebuild needed since `_layoutBand` is precomputed and `canvasHeight` is a getter that re-reads `showCrossCutting`. The `@track` decorator ensures re-render.

**Why `@track` re-renders both DOM and SVG height:** changing a tracked field invalidates getters used in template bindings (`canvasHeight`, `crossCuttingVariant`, the `if:true={showCrossCutting}` gate). LWC re-evaluates them on the next microtask.

- [x] **Step 1: Add describe block at end of existing CC describe**

  Reuse `CAPS_DATA_WITH_CC` already defined for the existing CC tests. Add a new describe:

  ```js
  describe('BcmCapabilityMap cross-cutting toggle', () => {
      let element;

      beforeEach(async () => {
          mockCapabilitiesImpl = jest.fn().mockResolvedValue(CAPS_DATA_WITH_CC);
          element = createElement('c-bcm-capability-map', { is: BcmCapabilityMap });
          document.body.appendChild(element);
          mockGetMaps.emit({ data: [{ Id: 'MAP-1', Name: 'Map 1' }], error: undefined });
          mockGetTags.emit({ data: [], error: undefined });
          await flushPromises();
          await seedLayout(element);
      });

      afterEach(() => {
          while (document.body.firstChild) document.body.removeChild(document.body.firstChild);
      });

      function getToggleButton() {
          // Cross-cutting button is the 6th lightning-button-icon in toolbar
          // Title-based selection is more robust:
          return element.shadowRoot.querySelector(
              'lightning-button-icon[title="Cross-cutting"]'
          );
      }

      it('Band is not rendered on initial load (default hidden)', () => {
          const bandNodes = element.shadowRoot.querySelectorAll('.bcm-band-node');
          expect(bandNodes.length).toBe(0);
      });

      it('Toggle button starts with neutral (border) variant', () => {
          expect(getToggleButton().variant).toBe('border');
      });

      it('Clicking toggle renders band and flips variant to brand', async () => {
          getToggleButton().dispatchEvent(new CustomEvent('click'));
          await flushPromises();
          const bandNodes = element.shadowRoot.querySelectorAll('.bcm-band-node');
          expect(bandNodes.length).toBeGreaterThan(0);
          expect(getToggleButton().variant).toBe('brand');
      });

      it('Clicking toggle twice hides band and resets variant to border', async () => {
          getToggleButton().dispatchEvent(new CustomEvent('click'));
          await flushPromises();
          getToggleButton().dispatchEvent(new CustomEvent('click'));
          await flushPromises();
          const bandNodes = element.shadowRoot.querySelectorAll('.bcm-band-node');
          expect(bandNodes.length).toBe(0);
          expect(getToggleButton().variant).toBe('border');
      });
  });
  ```

  Note: existing `BcmCapabilityMap cross-cutting band` describe currently asserts `.bcm-band-node` exists by default. With the new default-hidden behaviour, those assertions will break. Update them to first click the toggle on (or call `element.showCrossCutting = true` if the field is `@api`/exposed — it is not, so click the button).
